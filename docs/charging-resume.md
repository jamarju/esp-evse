# Charging resume

The ESP32 enable control uses an explicit positive-pilot B1 -> B2 sequence
when the AVR reports Connected, Sleeping, or Disabled and its charging relay
is open. It sends `FS`, waits for acknowledgement, holds B1 for at least
3 seconds, reads `GS` to confirm Sleep with the relay open, and sends `FE`.
If graceful Sleep is still opening the relay, it checks again after 1 second.
There is only one B1 -> B2 transition per accepted enable request, not a
periodic vehicle-wakeup retry. Repeated enables do not reset the dwell; off,
fault, command rejection, or a UART timeout cancel the sequence.

An already charging vehicle is not interrupted. State F (`FD` / -12 V), AVR
reboots, hardware current limits, calibration, and safety checks are not used
or changed. The current setpoint remains under the existing manager's control.

The September 25 EV2 experiment resumed using `FS` followed by `FE`, before
its experimental F fallback ran. That experiment does not establish why a
later EV1 restart took longer or prove an internal BYD anti-chatter timer.
The explicit dwell and Connected-state re-arm are new; long-pause recovery
still needs observation on the actual vehicle.

Host regression tests: `uv run python -m unittest discover -s tests -v`.
Release versions are generated by the existing push-to-main autobump workflow;
compile and deploy the resulting release commit, not the pre-bump commit.
